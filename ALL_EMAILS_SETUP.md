# RHYTHM — Complete email redesign

## What is live in this ZIP
- **Order confirmation** and **sandbox refund confirmation** are generated by Next.js using `src/lib/checkout/email-templates.ts`, with HTML and text versions. They are sent by the existing `email.ts` only after their corresponding events.
- **Signup OTP**, **magic-link/OTP**, **password recovery**, **email change**, **invitation**, and **reauthentication** have newly designed **paste-ready Supabase HTML templates** in `supabase-email-templates/`. These cannot be deployed by copying the Next.js ZIP. Install them individually in **Supabase Dashboard → Authentication → Emails → Templates**, selecting the corresponding template and replacing its source HTML. Use the subjects listed below.
- **Cancellation**, **failed payment**, **shipping**, and **delivery** templates have been prepared as TypeScript exports, but **are not wired to sending**. Do not claim these events occur automatically. Shipping and delivery only make sense with verified fulfillment events; this sandbox currently ships nothing.

## Supabase email subjects and matching files

| Dashboard template | File | Subject |
|---|---|---|
| Confirm sign up | `confirm-signup.html` | RHYTHM \| Confirm your email |
| Magic link or OTP | `magic-link-or-otp.html` | RHYTHM \| Your sign-in code |
| Reset password | `recovery.html` | RHYTHM \| Reset your password |
| Change email address | `email-change.html` | RHYTHM \| Confirm your email change |
| Invite user | `invite.html` | RHYTHM \| Your invitation |
| Reauthentication | `reauthentication.html` | RHYTHM \| Confirm it is you |

**Preserve template variables exactly:** `{{ .Token }}` is for numeric OTP emails, and `{{ .ConfirmationURL }}` for the link-based flows the existing app supports. Do not replace link-based recovery with a code without also updating the website recovery logic.

## Install and test
1. Copy your **existing working** `.env` (never upload or commit secrets). You do not need new database tables or migrations.
2. `npm.cmd install`, `npx.cmd prisma generate`, `npm.cmd run build`, `npm.cmd run dev`.
3. In Supabase, update templates individually; save each and preview. Your custom SMTP remains configured separately in Supabase.
4. Use a fresh test account and verify signup OTP and login OTP delivery. Use the recovery flow and ensure the reset link works. Trigger and inspect confirmation + refund emails from sandbox checkout. Test mobile rendering and plain-text clients.
5. Keep Gmail SMTP only for limited invited testers; it is not a dependable large-scale transactional email provider.

## Security notes
- Do not insert a user's arbitrary HTML directly into transactional templates; the existing template layer HTML-escapes dynamic fields.
- In the current version, order/refund email sending is tracked by `OrderNotification`. Prepared future templates are **not** active.
- All sandbox order emails clearly state that no money was charged and nothing ships.
- Tokens and reset links are sensitive; do not publish real emails or tokens in screenshots.
- Rotating previously exposed database and auth gate secrets is still recommended.
