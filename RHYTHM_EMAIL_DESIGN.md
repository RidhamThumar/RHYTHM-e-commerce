# RHYTHM — Email design system

Minimal luxury: ivory background (#f1eee9), white content, charcoal text, subtle dividers, generous padding, RHYTHM wordmark. HTML uses tables and inline styles for email compatibility and includes plain-text alternatives.

## Live templates in this version

1. Sandbox order confirmation: successful simulated payment only; summarizes items, size, quantity, amounts, and sandbox disclaimer.
2. Sandbox refund confirmation: after simulated refund; clearly states no actual money was moved.

Both are generated by `src/lib/checkout/email-templates.ts` and sent by `src/lib/checkout/email.ts`. The existing database tracking of SENT/FAILED/NOT_CONFIGURED remains intact. The optional `NEXT_PUBLIC_SITE_URL` sets the order-history link, e.g. `http://localhost:3000` for local preview or your deployed demo origin. Without it, no possibly broken button is shown. The sender remains `ORDER_SMTP_FROM` with `ORDER_SMTP_APP_PASSWORD`; keep credentials in `.env` only.

## Supabase Auth templates — configure on Supabase Dashboard

These cannot be changed by the Next.js order-email module. In Supabase → Authentication → Emails → Templates, use the same RHYTHM tone and keep the `{{ .Token }}` placeholder **exactly** as-is.

### Magic link or OTP
Subject: RHYTHM | Your sign-in code

Use the same HTML structure as above, with the heading "Your RHYTHM verification code." and instruction "Enter this code to continue signing in." Keep `{{ .Token }}` and the five-minute notice (only if Supabase expiry remains 300 seconds).

### Password recovery
Subject: RHYTHM | Reset your password

Use the matching header, a short security explanation, and Supabase's appropriate recovery link placeholder `{{ .ConfirmationURL }}` for the existing link-based recovery flow. Do not convert password recovery to OTP unless the website recovery route implements token verification.

## Future events — not wired to sending yet

- Order cancellation: "Your RHYTHM order has been cancelled." Include order number and whether any payment reversal actually occurred. Never claim a refund without a confirmed refund event.
- Shipping update: "Your RHYTHM order is on its way." Only send after a real shipment/tracking record exists. Do not claim dispatch in sandbox-only mode.
- Delivery confirmation: "Your RHYTHM order has arrived." Only send after a verified delivery event.
- Payment failed: "We couldn't complete your RHYTHM checkout." No paid order must be created; never request card details by email.

## Local test

1. Copy `.env` from your already working Phase 5 folder; do **not** include it in a ZIP or Git repository.
2. Run `npm.cmd install`, `npx.cmd prisma generate`, `npm.cmd run build`, then `npm.cmd run dev`.
3. Simulate a successful payment to receive the redesigned confirmation email. Verify purchased items, subtotal, shipping, total, and visible sandbox disclaimer.
4. Simulate a refund and verify the redesigned refund email.
5. Check both emails on mobile and desktop, including spam folders. Verify that email status is SENT in OrderNotification.

No schema change is required for these template updates. No need for `prisma db push`.
